# 문맥·기억 기법 채택안 초안 (검토 자료. 확정안은 DESIGN_KO.md 5절)

근거 노트: in_task_context.md, memory.md, effective_context.md (같은 폴더)
전제: v1은 표준 라이브러리, 손타이핑. 현재 모델 GLM-5.3-Flash(~1M), 이후 4B~32B 로컬 모델. 원칙 "기억은 모델이 아니라 하네스가 든다".

## A. v1에 넣는다 (구조·기록, 저비용)

A1. 문맥 조립 함수 단일화. 순서: [고정 접두부: 시스템 프롬프트+도구 정의] → [이력, append-only] → [끝: 상태 블록(선택)]. 접두부를 바꾸지 않아 prefix cache 유지. 근거: Manus/Anthropic 캐시 지침, Anthropic context editing이 지울 때마다 캐시 무효화(V).

A2. 도구 출력 래퍼(코어). 어댑터 도구 결과를 프로필의 max_tool_output 이하로 자름: 앞부분+뒷부분 유지, 가운데 생략 표시. 원문 전체는 관찰 저장소에 보관하고 핸들 반환. 코어 제공 도구 read_obs(handle, offset, length), grep_obs(handle, pattern). 근거: Manus 파일 오프로드(V, 수치 없음), Anthropic just-in-time, LongFuncEval: 도구 출력 길이 증가 시 7~91% 하락(S). 머리+꼬리 형태의 효과를 비교한 통제 연구는 없음(추론).

A3. 토큰 추정·보정. 문자 종류별 문자/토큰 비율(한국어 약 1.3~1.5, 영어 약 4, 초기값)로 추정하고, 매 응답의 usage.prompt_tokens로 이동평균 보정, 10% 여유. 매 호출 입력 토큰 기록. 근거: Qwen3-8B 한국어 약 1.34자/토큰(S).

A4. 프로필 필드: context_tokens(공칭), effective_ctx(실측, 미측정 시 null), context_tokens_safe(하네스가 쓰는 상한), max_tool_output, keep_last_tool_results, max_exposed_tools. 고정 비율(0.5~0.6) 대신 실측값 사용. 근거: RULER 소형 모델 유효 길이가 공칭의 25~50%(V), NoLiMa에서 Llama-3.1-8B 유효 약 1K(V).

A5. 상태 블록(구현은 v1, 기본 꺼짐). 하네스가 사실로만 만드는 JSON: 목표, 읽은 자료 핸들, 진행 단계, 남은 예산, 어댑터가 지정한 고정 사실(pinned). 시스템 프롬프트가 아니라 마지막 메시지에 붙임. 모델은 상태 필드만 바꿀 수 있음. 2단계 기본형 비교에서는 끔, 3단계 긴 업무에서 on/off 비교. 근거: Anthropic JSON이 덜 덮어써짐(V, 정성), Manus recitation(V, 수치 없음), 통제 연구 없음.

## B. 3단계(긴 업무)에서 켜고 효과를 잰다

B1. 관찰 마스킹. 최근 N개 도구 결과만 원문 유지(N: GLM 10, 작은 창 3~5), 이전 것은 핸들을 가리키는 복구 가능한 자리표시로 교체. 발동: context_tokens_safe의 70% 초과 시 40%까지. 어댑터가 지정한 고정 사실(ID·자격정보 등)은 상태 블록으로 옮겨 보존. 근거: JetBrains 비용 약 50%↓·성공률 유지(V), Anthropic 기본값 100k 트리거·최근 3개 유지(V), ACON에서 단순 FIFO 삭제는 어려운 과제 15.9로 악화(V) → 삭제가 아니라 복구 가능한 자리표시.

B2. 업무 분해(맵 워커). 독립 항목은 어댑터가 정의한 단위로 새 문맥에서 처리, 출력은 스키마 검증 후 합산. 근거: Anthropic 다중 에이전트 +90.2%·토큰 약 15배(V, 최상위 모델), 문맥 공유가 필요한 일에는 부적합(V). 작은 모델 근거는 추론.

B3. 모델 작성 메모(이전 S). 마스킹이 켜진 긴 업무에서만, 통째 재작성 금지, ID 붙은 항목 추가·수정(delta) 방식. 근거: ACE 통째 재작성 시 18,282→122토큰·정확도 66.7→57.1(V).

## C. 5단계(작은 모델)

C1. probe 문맥 측정 추가. 측정 토큰 기준 길이 1K/4K/8K/16K/32K(/64K), 깊이 0.1/0.5/0.9, 과제: 방해물 있는 문자 그대로 찾기, 한국어 비문자적 연상(NoLiMa식), 변수 추적, 도구 5/15/30개 실린 상태에서 도구 호출. 각 칸 5회, 온도 0. 지표: 1K 대비 85% 이상(절대 0.80 하한) 유지되는 최대 길이 → effective_ctx. 약 360회·600만 입력 토큰/모델. 근거: 노트의 제안(추론), HELMET: 단순 NIAH는 실제 과제 예측 못 함(V).

C2. 노출 도구 수 제한(max_exposed_tools). 근거: LongFuncEval 도구 수 증가 시 7~85%↓(S), Tool-DC 10→20개 시 작은 모델 타격(S).

C3. LLM 요약(compaction)은 최후 수단. 스키마 기반, 모델별 A/B 스위치. 근거: ACON 일반 프롬프트 압축 시 AppWorld 어려운 과제 39.7→23.8(V), 학습된 압축기는 Qwen3-14B 25.6→33.9(V, 학습 필요), JetBrains Gemini 2.5 Flash 40.4→31.4(V).

## D. 6단계(업무 간 기억)

D1. 강한 모델·사람이 쓴 플레이북을 작은 모델이 읽게 함. 근거: Agent Memory Distillation Qwen3-4B AppWorld 자기 메모 14.88→16.07, 교사 메모 →49.40(V); Dynamic Cheatsheet 이득은 규모에 강하게 의존(V).
D2. 함수 메모: 도구 오류 시 함수 이름으로 조회해 주입(결정적, 임베딩 불필요). 근거: 위 논문(V).
D3. 관리 규칙: 검사 통과 또는 사람 승인 사례만 저장, 출처 기록, 후보→승인→폐기, 반복 실패 연관 항목 삭제, 1건만 최소 점수 이상으로 조회. 저장소는 sqlite3 FTS5 BM25(한국어는 trigram 토크나이저). 근거: 2505.16067 add-all 최악·엄격 수용+삭제 최선(V), MINJA 주입 98.2%(V), BM25 대 임베딩 비교 연구 없음.
D4. 큐레이션된 스킬(SKILL.md, 집중형 ≤3모듈). 근거: SkillsBench 33.9→50.5%(V).

## E. 채택하지 않음

- 모든 경험 저장(add-all), 메모 통째 재작성, 시스템 프롬프트에 바뀌는 메모 넣기
- 임베딩·벡터 DB(오프라인 의존성), 기본값으로서의 일반 LLM 요약
- 문맥 공유가 필요한 업무의 다중 에이전트
- 오래된 사고 블록 삭제: 근거(2609.29875, 초록만)가 약하고 GLM은 Preserved Thinking 시 원문 반환 요구 → 프로필 플래그로만 보류
