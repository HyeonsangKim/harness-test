# 도구 없는 하네스 공개 벤치마크 계획

## 왜 하나

지금까지는 직접 만든 과제 두 묶음으로만 쟀다. 이 과제는 계산이 많도록 짜서 하네스에 유리할 수 있다. 남이 만든 공개 벤치마크에서도 같은 결과가 나오는지 확인한다.

비교 기준에는 사고 모드를 반드시 넣는다. "그냥 답하기"(사고 끔)만 기준으로 두면 하네스의 장점이 부풀려 보인다.

## 데이터

| 벤치마크 | 내용 | 라이선스 | 받는 곳 | 쓰는 범위 |
|---|---|---|---|---|
| TAT-QA | 실제 재무 보고서의 표와 본문을 보고 답하는 문제 | CC-BY-4.0 | `huggingface.co/datasets/next-tat/TAT-QA` (`tatqa_dataset_dev.json`) | 계산형 질문(`answer_type = arithmetic`) 100문항 |
| GSM-Hard | GSM8K의 숫자를 크게 바꾼 수학 문장제. PAL 논문(arXiv 2211.10435)이 만든 벤치마크 | MIT | `huggingface.co/datasets/reasoning-machines/gsm-hard` (`gsmhardv2.jsonl`) | 100문항 |

- **표본:** 고정 시드로 무작위 추출하고, 문항 번호 목록을 실행 전에 커밋한다.
- **TAT-QA 쪽 사용 파일:** test 정답 파일 대신 정답이 공개된 dev 파일을 쓴다.

## 조건

| 조건 | 내용 |
|---|---|
| P | 사고 끔, 그냥 답하기 |
| PT | 사고 켬, 그냥 답하기 (공정한 기준) |
| RT | 최종 하네스: 파이썬 + 검사 + 표 파일 + 바로 끝내기 |
| RT2 (후보) | RT + 두 번 짜서 대조: 같은 문제를 다른 방식의 코드로 한 번 더 풀고, 결과가 다르면 차이를 보여 주고 다시 판단하게 함. 근거는 PAL의 프로그램 다수결 |

## 채점

- **TAT-QA:** 공식 평가 스크립트(GitHub `NExTplusplus/TAT-QA`의 `tatqa_eval.py`)의 숫자 비교 규칙을 따른다. 단위(scale)와 반올림 처리를 실행 전에 원문으로 확인해 이 문서에 적는다.
- **GSM-Hard:** 정답 숫자와 비교한다. 소수점 오차 허용 범위는 실행 전에 정한다.

## 지표와 판정

- **지표:** 정확도, 토큰, 대기 시간.
- **통계:** 지금까지와 같다. 문항별 짝 비교, 부트스트랩 95% 신뢰구간, 부호 검정.
- **질문 1: 하네스가 사고 끔보다 정확한가?** RT − P의 하한이 0보다 크면 그렇다.
- **질문 2: 하네스가 사고 켬과 비교해 어떤가?** RT − PT의 정확도 차이와, 토큰·시간 비율을 그대로 보고한다. 미리 기대하는 방향을 정하지 않는다.
- **질문 3: 두 번 짜서 대조하는 판은 효과가 있는가?** RT2 − RT의 하한이 0보다 크면 채택한다.

## 실행

- **장소:** 사외 Mac (Qwen3.5-9B Q8_0, llama.cpp). 데이터를 받아야 해서 사외에서만 돌린다.
- **규모:** 200문항 × 4조건 = 800건.
  - PT는 한 건에 2~3분 걸린다.
  - 동시 6개로 돌리면 PT를 포함해 약 3~4시간이 걸린다.
- **순서:**
  1. 데이터를 받고 표본과 채점 규칙을 고정한다.
  2. 사전 등록 커밋을 한다.
  3. P, RT를 돌린다.
  4. PT를 돌린다.
  5. RT2를 돌린다.

## 한계

- 둘 다 영어 벤치마크다. 한국어 업무에 대한 근거는 계속 직접 만든 과제로 본다.
- GSM-Hard는 공개된 지 오래돼서 모델이 학습 중에 봤을 수 있다. 조건 간 비교는 같은 모델끼리라 영향이 적지만, 점수 자체를 다른 연구와 비교하지는 않는다.
